# 可复用的 AI PC 工作流

这些是工程工作流说明，不宣称已通过第二台设备或全新环境的部署验收，也不宣称PYNQ Skill额外加分已获得。

| 工作流 | 适用范围与使用方法 | 来源与已验证效果 | 失效条件 |
|---|---|---|---|
| GPU与ROS隔离 | GPU跑视觉，系统Python单独发布ROS；见host/app/scripts/start_vision.sh | 本机先前同解释器ROCm+FastDDS原生分配器崩溃，拆进程后已有历史运行记录 | 新机需重新验证驱动/依赖；进程间时间戳仍需校验 |
| RGB-D到TCP契约 | 复用calibration.py、geometry.py和pickup.py；先实测外参/TCP，再按ID冻结并确认 | 当前单元测试验证非单位变换、米/毫米、姿态/配置拒绝、ACK回显 | 相机移动、深度缺失、无实测TCP、模型/ID变化 |
| 有界暂存与目标锁定 | 使用TemporalTracker，历史点标记不可用；执行目标只在确认后锁定 | 人工噪声/跳变/漏检测试与软件回归通过；不代表真实抓取精度 | 目标交叉、长遮挡、相似工具换位，不能保证身份永不丢失 |
| 按拍摄场次留出 | 同场次、相邻帧及增强图保持同一split；测试集禁止训练 | 保留124图/393框的完整场次作为冻结测试，源哈希随包 | 同一天、同工具、同背景仍然相关，不能代表陌生工作台 |
| 指标审计打包 | host/deploy/retest.sh重新生成独立结果目录；对比原始CSV及源哈希 | 本次从副本运行软件测试与模型测量；文件完整性校验随包 | 重新训练、换驱动或输入规格后必须重测，不复用旧速度 |

CPU、GPU、网络测试顺序执行，避免相互争用资源。启动首个CPU预测后重新设置线程数，避免Ultralytics自动线程重设污染比较条件。
Ultralytics评估可能自动下载绘图字体；部署脚本使用本地DejaVu字体缓存，以免离线评估因字体联网阻塞。


本文件为合并包的分项工作流，所有路径以提交包根目录为基准；统一入口见 skill/readme.md。
