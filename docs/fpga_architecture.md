# 系统架构与职责

当前可证实的执行链路：PC Python操作台→XSCT/JTAG→Zynq DDR命令区→PS Cortex-A9应用→AXI4-Lite运动邮箱→PL命令状态机/AXI CAN→CAN收发器→六轴电机。夹爪由PS经独立AXI PWM外设输出到W19。反馈反向通过CAN接收服务、协议检查和按轴状态缓存进入PS报告及PC显示。

当前路径包含运动学求解、批次下发、状态检查、显式指令和故障锁存。AI本地感知/决策节点是参赛目标，当前归档工程没有证明已经部署并参与上述闭环；见 `host/model/model.md`。图中的虚线AI节点表示待补。

PC负责交互、任务编排、日志和将来AI感知。PS负责运动学、轨迹、标定与执行状态、安全检查和PWM服务。PL承担硬件CAN事务、协议反馈、AXI邮箱及独立PWM，不是普通串口/GPIO转接板。电机内部闭环由驱动固件执行；本工程PS/PL调度不是电机内部FOC频率。

CAN与PL时钟设计值分别20MHz和50MHz。控制策略为“本组目标执行与核验完成后，再等待50ms”，不能等同固定20Hz或100Hz。
