# 数据流、时序与异常处理

1. PC由 `workflow_protocol.py` 构造单调序号、操作码、参数/标定记录及CRC32的DDR请求。
2. `workflow_bridge.tcl` 仅通过APU系统内存目标访问受限DDR区间；正常后台worker单独拥有桥接进程。
3. PS校验CRC、序号、会话/标定与状态；执行明确的请求，或拒绝并返回状态。运动学求解和轨迹在PS完成。
4. PS通过0x40000000运动邮箱提交，PL序列化CAN事务。0x40001000为独立舵机PWM；不通过CAN FIFO驱动舵机。
5. CAN反馈经PL接收与协议验证进入逐轴缓存。PS更新DDR报告，PC轮询显示并记录JSONL。
6. STOP、心跳失联及故障可禁止继续提交并停用PWM。日志里存在停止未确认，发出请求和进入软件锁存不能自动证明机械安全状态。

PC日志使用单调时钟记录阶段事件；PS使用板端计时器。现有材料没有经过验证的PC与PS跨时钟同步误差数据。因此不能跨域直接相减获得单向通信或传感器到实际动作的端到端延迟。正式补测优先用RTT，物理响应使用同一示波器/逻辑分析仪/高速视频时基，明确帧周期和误差。
