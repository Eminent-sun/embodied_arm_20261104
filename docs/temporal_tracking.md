## 数据流

同帧 RGB-D → 工具框 / 手部关键点 → 深度质量检查 → 目标关联 → 三维滤波 →
绑定验证后的基座变换 → 原子 JSON → TCP 7011 → PS 观测存储及 ACK。

- 新工具轨迹需要 ≥0.35 置信度。已有轨迹可关联 ≥0.18 的弱检测，避免置信度在阈值附近造成断轨；
  弱检测不能更新执行参考点。`--confidence` 可调整新轨迹与合格坐标门槛。
- 同类别框做一对一 IoU 关联；两个候选接近时拒绝模糊关联，短时暂存旧轨迹。
  ID 只在 source_session_id 内有效，不能保证交叉、完全遮挡后仍能识别同一件实物。
- 连续 ≥3 次匹配且 ≥3 次有效三维测量才合格。滤波是三点中值 + 时间常数 100 ms 的 EMA，
  1.5 mm 死区；检测框也独立平滑。先滤相机坐标，再用同一外参转换基座坐标。
- 相对滤波点超过 30 mm 的单次跳变不更新点，标记 `jump_rejected`。
  连续三次落在一致的新位置后重建滤波状态，再累计三次有效测量；不会缓慢吸收离群大跳变。
- 漏检或深度无效时最多保留 350 ms 历史点，橙色显示并标记 `held` / `missing_depth`。
  `coordinate_fresh=false`、`coordinate_usable=false`；到期移除坐标或整个轨迹。
  不做无观测的速度外推，不把历史点标成新测量，不保证永不丢目标。
- `coordinate_age_ms` 是该点最后一次通过过滤的测量年龄；发送端加上处理/发送前延迟。
  发送时 >150 ms 禁止更新参考点，>350 ms 清空工具三维点。
  网络传输时间未包含，PS 按接收后的单调时钟继续累加每点年龄，150 ms 禁用、350/200 ms 清空工具/手点，另按独立帧 TTL 到期失效；这不是硬实时控制协议。
- 原始测量留在 `raw_surface_point_camera_m`，滤波值放在 `surface_point_camera_m`。
  前者用于诊断；通信与显示使用后者。滤波三维点投影十字用于指示位置。
  `depth_quality` 对暂存点描述最后一次合格采样，是否当前测量必须看 freshness / age 字段。

配置位于 `config/vision_station.json` 的 `temporal_filter`。默认值针对桌面静止工具；
真实视频要检查滤波延迟与实际运动，不能把滤波后的平滑程度当成绝对定位精度。
框中心可能落在桌面而不是细工具上。当前点是表面定位参考，不是夹爪抓取位姿；
尚需工具分割/轴向、夹爪 TCP、姿态与碰撞规划验收。

## 人手

MediaPipe 仍独立检测每手 21 点。每点使用同帧有效深度和相机内参计算米制 XYZ，
不使用归一化 landmark z 充当米制深度。每点独立中值/EMA/死区滤波，100 mm 跳变拒绝；
2D 关键点独立平滑以减少骨架闪动。按位置匹配手 ID，不仅按 Left/Right 标签。

手关键点最多暂存 200 ms，标明每点 freshness/age。手部存在提示保留 500 ms，
避免一帧漏检立刻显示作业区清空。没有检测到手不代表安全；此模型不是安全认证通道。
通信新增 `hands[].keypoints[]` 的 camera_m、base_m、freshness 与 age；
最多两只当前手及两条短时历史轨迹。无深度的点为 null，二维骨架仍可显示。

## 可视化与锁定

打开 http://127.0.0.1:8080：

- 当前检测表显示目标 ID、类别、状态、年龄、相机 XYZ 与基座 XYZ（m）。
- 手表显示手腕（0）与食指尖（8）；完整 21 点在原始检测 JSON 和传输 payload 中。
- “PS 最后确认”直接读取发送进程记录的同一 payload 与 ACK，不从当前画面重新拼接数值。
  未连接、已断开、过期和未确认均明确标记；历史 ACK 不冒充仍在线。
  `runtime/vision/link_status.json` 保存该记录；发送默认 10 Hz，显示观测可能比 ACK 新。
- 按具体 ID 选择目标，再生成草案。多个同类工具不能自动选择当前最高置信度。
  草案保存固定 `source_session_id + track_id + calibration_id` 与确认时的三维点。
  `/api/task/<task_id>` 复核同一目标；丢失/暂存时等待，换会话/标定或移动超过 10 mm 要重新确认。
  不会自动切换到同类另一件工具，也不会每帧覆盖已确认的位置。
- 草案和目标锁定均不发送电机指令，执行按钮仍关闭。真实运动管理器、PS/PL 停止联锁尚待接入。
  “坐标暂存”解决显示连续性；运动中遇到视觉异常应由执行管理器决定受控暂停/重新规划，
  不能通过无限保留旧坐标掩盖异常。

## 软件回归验证

运行：

```bash
PYTHONPATH=vision:communication .venv-vision/bin/python -m unittest discover -s tests -v
.venv-vision/bin/python scripts/verify_temporal_filter.py
```

`runtime/temporal/report.json` 和 `filter_comparison.png` 是明确标记为 synthetic_test 的模拟扰动：
基于保存的七件工具检测结果人为添加毫米级噪声、150 mm 突变及三帧漏检；不是现场视频。
该序列 X 标准差从 3.91 mm 降至 1.55 mm，突变被拒绝，漏检暂存期间不可更新目标。
三帧通过实际 TCP 接收，接收端 received_payload 与界面所读的 ACK 文件 payload 完全相同；其 observation 字段另按接收后经过时间更新有效性。
真实硬件、现场遮挡及交叉运动仍需实测；不宣称零抖动、零丢失或保证抓取成功。

当前 36 项回归测试通过；新版默认权重的真实历史 RGB-D 重放检出 7 件工具，7 点深度有效，PS ACK 3 帧。
