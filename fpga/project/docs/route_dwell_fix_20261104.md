# RUNPATH v2：精简路径与固定等待

本次仅更新电脑路径脚本。若已在当前修复版上正常完成上一轮各段运动，不用重新下载 BIT/ELF，也不用仅为本次更新重做标定。

## 等待为什么卡住

实机日志 `software/operator_logs/20261104_133116/recorded_cycle.jsonl` 的保留快照中，拾取后的 5 秒等待在约 62.58 秒内重置了 34 次。原因是保持期间偶发速度读数超出到位阈值，旧脚本就重新计时；没有发送闭爪命令。

现在到位并连续确认停稳后，设置固定截止时间，并显示逐秒倒计时。轻微反馈波动不重置 5/3/2 秒计时；原有范围、速度、跟随误差、目标不变、标定不变、故障和夹爪监测继续生效。计时结束后，夹爪动作前仍要在最多 5 秒内确认连续三次停稳；持续不稳会报错取消，不会无限等待或强行闭爪。

## 新的一次完整流程

坐标顺序：`X Y Z Roll Pitch Yaw`，位置 mm，角度 °。

| 顺序 | 操作 / 目标 |
|---|---|
| 启动 | 本次有效标定的 INITIAL_HOLD，夹爪完全打开 1110 μs，等待 PWM 到达 |
| 运动 1 | 直接到拾取点 `180 0 160 0 0 0` |
| 拾取 | 确认到位后固定等待 5 秒，再闭合到 1490 μs，等待 PWM 到达 |
| 运动 2 | 保持拾取姿态抬高 10 mm：`180 0 170 0 0 0` |
| 运动 3 | 直接到递送点 `180 -150 170 -60 -90 0` |
| 递送 | 确认到位后固定等待 3 秒，打开到 1110 μs，等待 PWM 到达，再固定等待 2 秒 |
| 运动 4 | 保持递送姿态抬高 30 mm：`180 -150 200 -60 -90 0` |
| 运动 5 | GOHOME 返回当前 SAVEINITIAL 保存的初始位，保持 INITIAL_HOLD、夹爪打开 |

原 30 段精简为 5 段。拾取点、拾取后抬升点、递送点分别对应原日志 request 54、53、155；递送后抬升点为新增离线验证点。用户已确认没有需要避让的障碍物或最低高度要求。

不采用拾取姿态全零时直接抬到 Z=200 的方案：该目标在当前标定和现有限位下被规划器拒绝，未用于交付路线。

每段仍采用现有五次曲线关节插值、末端停稳；不是末端直线运动，也不是途经点不停顿的连续轨迹。通过减少 25 次分段停顿改善顺滑度，速度/加速度限制没有提高。夹爪全行程渐变约 3.8 秒，另计于指定的等待时间；PWM 到达不代表实物抓握得到传感器确认。

## 现在怎样使用

1. **已经启动的旧 RUNPATH 不会中途更新。** 如果旧流程仍卡在等待，先承托机械臂，再按一次 Ctrl+C 取消当前路径。它会请求 STOP，电机可能失去保持力矩。不要连续按 Ctrl+C 或直接关窗口；等待回到 `ARM>`。
2. 输入 `STATUS`。若为 FAULT_LOCKED，排除实际异常后输入 `RECOVER`，再 `STATUS`。仅当本次六轴标定和 SAVEINITIAL 仍有效、方向未变、电机未断电且零点关系没有改变时，才输入 `RESUME` 使能并保持当前位置。RESUME 不会自动回初始位或续跑。
3. 在有效保持状态输入 `GOHOME`，等待 `STATUS` 为 INITIAL_HOLD，`error=0`、`enabled_mask=0x3f`、`calibrated_mask=0x3f`、`model_initial_saved=True`，并确认机构停稳。GOHOME 会实际运动。
4. 输入 `PATHINFO` 查看目标，再显式输入 `RUNPATH`。当前这版控制台会在每次 RUNPATH 前重新载入路径模块；应首先显示 **`RUNPATH v2：5 段精简路线；5/3/2 秒固定计时，轻微反馈波动不重置。`** 无需为了加载此路径模块退出窗口。
5. 如果旧流程已自行完成并返回 INITIAL_HOLD，直接按第 3～4 步确认后进行下一轮，无需为更新执行 STOP。若发生电机断电、重新下载或零点关系变化，按总说明重新完成实物 HOME 标定，不导入历史标定替代。

等待期间控制台忙于执行整轮流程，不接收 `ARM>` 文本命令；Ctrl+C 会取消并请求 STOP。每轮只执行一次，不自动重复。

## 验证及适用范围
