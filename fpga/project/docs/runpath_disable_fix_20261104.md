# RUNPATH 打开夹爪后六轴失能：排查与修复

## 日志确认的过程

现场日志：`software/operator_logs/20261104_124450/recorded_cycle.jsonl`。

1. 前置检查通过，六轴标定和初始位有效。
2. 请求 11、12、13 的夹爪设置/状态查询均成功；1110 μs 打开输出已完成。
3. 请求 **14，MOVETO 200 0 300 0 -90 0，返回 `[14,2,107,0]`**，即 PATH_BAD_GEOMETRY。
4. 旧 RUNPATH 把这一规划拒绝当作需停止的异常，立即写 STOP，日志明确记录 `stop_requested=true`。因此本次六轴失能有明确的软件停止请求来源。

旧日志没有保存失败时的 Cartesian 报告和逐轴实时反馈，不能断言当时具体是哪一轴或偏差多少。不能把以下复现偏差当成现场实测值。

## 离线复现与针对性修复

使用这次现场的 `calibration_latest.json` 作为离线测试夹具，运行旧的 ARM ELF：理想 HOME 反馈时首段规划成功；给第 3 或第 5 轴的电机位置加 -0.0004 rad 偏差时，首段返回相同的几何错误。两轴 HOME 位于模型上限，这一很小的反馈偏差使模型起点落在限位外。此前完整验证使用理想跟踪，没有覆盖此情况。

修复包括：

- PS 规划：只对测量得到的轨迹起点向原关节边界投影，最大 0.001 模型 rad，并同时受已有起点/到位容差约束。目标、全部发出的路径点及电机范围仍严格在原限位内；不修改原始反馈、标定或 STOP/故障保护。更大偏差仍拒绝规划。
- 电脑脚本：RUNPATH 先检查首段规划，成功才打开夹爪和开始移动。
- 明确的未执行规划拒绝：只有重新确认原保持状态、原目标未变、反馈停稳、标定与夹爪状态正常，才取消剩余流程并保留力矩，不发送 STOP，不自动重试。故障、通信不确定、目标改变或 Ctrl+C 仍请求 STOP。
- 日志：无论规划成功或拒绝，都保存完整 Cartesian 报告；取消/异常还保存最近一次逐轴反馈和目标，便于继续排查。

新增复现验证覆盖正常 HOME、两轴正反方向小偏差、超出 0.001 rad 的拒绝，以及 CHECKPOSE/MOVETO 被拒绝后保持六轴使能且不再执行后续动作。完整 30 段验证改用本次现场标定，起始同时注入第 3、5 轴 -0.0004 rad 偏差。

测试报告：`software/reports/recorded_start_reproduction.json`、`software/reports/recorded_cycle_arm_path.json`；修复前证据及原软件保存在 `history/before_runpath_hold_fix_20261104/`。离线验证不代表实物带载、碰撞和抓握已验证。

## 必须更新后再操作

本修复改动了 **PS 的 ELF 和电脑脚本**；BIT 保持不变。仅关闭重开控制台不能更新板上 PS 程序。

1. 承托机械臂，关闭旧控制台，断开电机和夹爪执行器电源。
2. 双击本目录 `00_control.cmd`，菜单选 **1**，重新下载当前配套程序，等待 `ARM_GRIPPER_DOWNLOAD_DONE`。该菜单会同时加载未改动的配套 BIT 和新 ELF。
3. 恢复执行器电源，菜单选 2，按总说明重新完成本次实物 HOME 的 CONFIGHOME、BEGIN、逐轴 CAL、SAVEINITIAL。不得在任意姿态照抄 HOME 角度；不得直接恢复随包历史标定。
4. 输入 STATUS，确认 INITIAL_HOLD、六轴有效且停稳，再输入 PATHINFO、RUNPATH。
5. 若显示“规划被拒绝，保留电机保持力矩”，保持控制台开启并输入 STATUS 查看，保留新日志，不直接重复运行。关闭窗口仍会请求 STOP，可能解除力矩。

修复和验证期间没有连接板卡、下载程序、使能或驱动实物机械臂。
