# INITIAL_HOLD 后 RUNPATH 仍被前置检查拒绝

用户提供的 STATUS 已是 INITIAL_HOLD，63/63 帧完成，无故障；所贴位置和速度也满足到位容差。旧 RUNPATH 另读一次反馈，只要那一次没有满足停稳/初始位条件，就统一提示“先 GOHOME”，且拒绝发生在日志记录前。因此不能由较早的 STATUS 确定实际拒绝瞬间哪一轴或哪项条件未通过。

本次修复统一了电脑端检查：

- 前置检查在同一个 INITIAL_HOLD 目标下等待最多 5 秒，连续 3 个采样满足原位置、速度及保存初始位的容差后才通过；不发送运动或夹爪命令。
- 不满足时保存 `hold_not_ready`，包含逐轴位置、速度、目标、保存初始位与实际阈值；不再一律提示重复 GOHOME。
- 每段完成需要连续 3 次到位；夹爪动作前也检查连续停稳。夹爪 PWM 渐变期间，短暂未达到到位速度阈值会等待，不因单次采样直接解除六轴力矩；超出原安全范围或超时仍中止并请求 STOP。
- 当前 v2：停留计时前确认停稳，之后使用固定 5/3/2 秒截止时间；轻微反馈波动不重置，安全监测继续生效，夹爪动作前再有限确认停稳。旧版重新计时逻辑造成等待卡住，已替换。
- 原有限位、到位容差、速度/跟随保护及心跳保护不放宽。只重试明确未执行的 result=6；已接受的运动不重发。
- 新控制台在每次显式 RUNPATH 前载入当前路径脚本，后续同类路径脚本更新可在两轮之间加载。已启动的整轮不会中途切换脚本。

本次 ELF/BIT 均未修改，不需要重新烧录。当前旧控制台需重开一次才能加载控制台更新；退出仍请求 STOP，先承托。

重开与恢复：

1. 承托机械臂，在当前 ARM> 输入 QUIT，等程序回到菜单，选 5 重连。
2. STATUS；若 FAULT_LOCKED，则先排查显示原因，再 RECOVER、STATUS。RECOVER 不使能、不移动。
3. 只有电机电源与零点关系未变，且标定仍为 0x3f、初始位有效，才显式 RESUME、STATUS，保持当前位置。
4. 在可用保持状态显式 GOHOME，等待 STATUS 到 INITIAL_HOLD 且停稳，再 RUNPATH。
5. 如果前置等待仍超时，保持窗口开启，输入 STATUS 并保留新会话的 `recorded_cycle.jsonl`；无需为了该提示重新下载或盲目重做 CAL。

旧控制台退出后的恢复可能暂时失能，不应在无承托情况下操作。若电机期间断电或零点关系变化，不能使用上述保留标定恢复，应重新进行实物 HOME 标定。

验证覆盖前置瞬时/持续未停稳、夹爪期间短暂反馈变化、固定等待抗反馈波动、故障和安全阈值异常；完整 ARM 离线验证还在前置阶段注入短暂超出到位速度阈值的反馈，并保留首段规划/移动的 result=6 注入与原边界偏差测试。未连接或操作实物硬件。
